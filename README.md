# Hoppa (הופה) — מערכת לניהול תהליך מעבר דירה

אפליקציית ווב (React + TypeScript + Vite + Tailwind + Supabase) לניהול מעבר דירה מא' ועד ת': הרשמה/התחברות אמיתית, צ'ק-ליסט חכם המבוסס על תאריך המעבר, מרקטפלייס ספקים עם מנגנון לידים, בונה חבילת שירותים, מחשבון תקציב עם עדכון אוטומטי, ספרייה של ספרים/מדריכים מומלצים, וממשק ניהול (Admin) לניהול משתמשים, ספקים, לידים ותוכן — הכול מגובה במסד נתונים אמיתי (Postgres דרך Supabase) עם multi-user ואבטחת שורות (RLS).

## ארכיטקטורה

- **Frontend:** React + TypeScript + Vite + Tailwind, `react-router-dom` עם `HashRouter` (כך שאין צורך בהגדרות rewrite בצד השרת לצורך רענון עמוד).
- **Backend:** Supabase — Postgres + Auth (אימייל/סיסמה, עם מקום מוכן ל-Google בהמשך) + Row Level Security לכל טבלה, כדי שכל משתמש יראה רק את הנתונים שלו, ואדמינים יראו הכול.
- **State:** `src/store/AppContext.tsx` שולף ומעדכן את הנתונים מול Supabase, כולל עדכון אופטימי בממשק לפני שהשרת מאשר.
- **Hosting מומלץ:** Vercel (חיבור ישיר ל-GitHub, בנייה אוטומטית בכל push).

## הרצה מקומית

```bash
npm install
cp .env.example .env   # ומלאו את הפרטים שלכם מ-Supabase (ראו למטה)
npm run dev
```

בלי להגדיר `.env` האפליקציה תציג מסך "נדרשת הגדרת חיבור למסד הנתונים" במקום לקרוס.

## שלב 1: הקמת פרויקט Supabase (חינמי)

1. היכנסו ל-[supabase.com](https://supabase.com) והתחברו/הירשמו.
2. לחצו **New Project**, בחרו שם וסיסמת מסד נתונים (שמרו אותה בצד), ובחרו אזור קרוב (למשל Europe).
3. המתינו כ-2 דקות להקמת הפרויקט.
4. עברו ל-**SQL Editor** בתפריט הצד, פתחו שאילתה חדשה, הדביקו את כל תוכן הקובץ [`supabase/schema.sql`](./supabase/schema.sql) מהריפו הזה, ולחצו **Run**. זה יוצר את כל הטבלאות, כללי ה-RLS, וממלא ספקים ותבניות משימות לדוגמה.
5. עברו ל-**Project Settings → API**. תצטרכו שני ערכים:
   - **Project URL** → `VITE_SUPABASE_URL`
   - **anon public key** → `VITE_SUPABASE_ANON_KEY`
   (שני הערכים האלו בטוחים לחשיפה בצד הלקוח — הם מוגנים על ידי כללי ה-RLS שכבר הרצתם.)
6. (מומלץ ל-MVP/דמו) תחת **Authentication → Providers → Email**, אפשר לכבות זמנית את "Confirm email" כדי להירשם ולהתחבר מיד בלי לאשר מייל. בפרודקשן אמיתי מומלץ להשאיר את זה דלוק.

### הפיכת עצמכם למנהלי מערכת

1. הריצו את האפליקציה (מקומית או בפריסה), עברו למסך **הרשמה**, והירשמו עם המייל שלכם.
2. חזרו ל-**SQL Editor** בפרויקט Supabase והריצו (עם המייל שנרשמתם איתו):
   ```sql
   update public.profiles set is_admin = true where email = 'you@example.com';
   ```
3. התחברו מחדש (או רעננו) — עכשיו יש לכם גישה ל-`#/admin` עם ניהול משתמשים, ספקים, לידים ותוכן.

## שלב 2: פריסה ל-Vercel

1. ודאו שהריפו הזה דחוף ל-GitHub (הענף `claude/moving-day-management-i394ew` או `main`, לפי מה שתבחרו).
2. היכנסו ל-[vercel.com](https://vercel.com), התחברו עם GitHub, ולחצו **Add New → Project**.
3. בחרו את הריפו. Vercel מזהה אוטומטית שזהו פרויקט Vite (Framework Preset: Vite, Build Command: `npm run build`, Output Directory: `dist`) — אין צורך לשנות כלום.
4. תחת **Environment Variables** הוסיפו:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
   (אותם הערכים משלב 1.5)
5. לחצו **Deploy**. בכל push לענף המחובר, Vercel יבנה ויפרוס אוטומטית גרסה חדשה.
6. אחרי הפריסה, כנסו לכתובת שקיבלתם, הירשמו, והפכו את עצמכם לאדמין כמו למעלה (אותה שיטה — פשוט הריצו את שאילתת ה-SQL עם המייל שנרשמתם בו דרך הכתובת החיה).

## משתני סביבה

| משתנה | איפה משתמשים | הערה |
|---|---|---|
| `VITE_SUPABASE_URL` | מקומי (`.env`) + Vercel | כתובת הפרויקט מ-Project Settings → API |
| `VITE_SUPABASE_ANON_KEY` | מקומי (`.env`) + Vercel | מפתח ה-anon/public — בטוח לחשיפה בצד לקוח |
| `VITE_BUSINESS_WHATSAPP` | מקומי (`.env`) + Vercel | אופציונלי: מספר וואטסאפ של העסק לכפתורי יצירת קשר |

**לעולם אל תשתמשו ב-`service_role` key בצד הלקוח** — הוא עוקף את כל כללי ה-RLS ואסור שיגיע לדפדפן.

## מבנה מסד הנתונים (`supabase/schema.sql`)

| טבלה | תיאור |
|---|---|
| `profiles` | פרופיל משתמש (נוצר אוטומטית עם כל הרשמה), כולל `is_admin` |
| `providers` | ספקי המרקטפלייס (קריאה לכולם, כתיבה לאדמינים בלבד) |
| `task_templates` | תבניות ברירת המחדל של הצ'ק-ליסט (CMS, עריכה לאדמינים בלבד) |
| `tasks` | המשימות בפועל של כל משתמש (נוצרות מ-`task_templates` בסיום ה-Onboarding) |
| `leads` | פניות של משתמשים לספקים במרקטפלייס |
| `budgets` / `budget_categories` | תקציב הגג וההוצאות לפי סעיף, לכל משתמש |
| `package_selections` | הבחירות בבונה חבילת השירותים |
| `service_requests` | בקשות להזמנת שירות מלא (גם מגולשים לא מחוברים, insert בלבד) |
| `service_items` | שלבי תוכנית המעבר של כל הזמנה, הלקוח רואה רק את שלו |

כל הטבלאות מוגנות ב-Row Level Security: משתמש רגיל רואה/עורך רק את הנתונים שלו; משתמש עם `is_admin = true` רואה הכול (ובספקים/תבניות — גם עורך).

## שירות מלא: "מעבר דירה בלי לעשות כלום"

בנוסף למרקטפלייס, Hoppa מוכרת חבילות שירות מלא במחיר קבוע ומתאם את כל הספקים בעצמו.

- **עמוד חבילות ציבורי** (`#/services`): שלוש חבילות (בסיס, מלא, פרימיום), מחשבון הערכת מחיר לפי גודל דירה, תוספות ומעבר בין ערים, וטופס בקשה שעובד גם בלי התחברות.
- **"המעבר שלי"** (`#/my-move`): פורטל ללקוח המחובר. מציג סטטוס הזמנה, מחיר, ותוכנית מעבר עם תאריכים, ספקים וסטטוס לכל שירות.
- **אדמין → הזמנות שירות** (`#/admin/services`): ניהול הבקשות. עדכון סטטוס, מחיר סופי והערות, שיוך בקשה לחשבון לקוח לפי אימייל, ויצירת תוכנית מעבר מתבנית החבילה (התאריכים מחושבים מתאריך המעבר). המסך מציג גם הכנסות והערכת רווח גולמי.

**מחירים ותכולת חבילות** מוגדרים בקובץ אחד: [`src/data/servicePackages.ts`](./src/data/servicePackages.ts). המחירים שם הם הערכות התחלתיות לבדיקת שוק.

**וואטסאפ:** אם מגדירים `VITE_BUSINESS_WHATSAPP` (פורמט בינלאומי, למשל `972501234567`), מופיעים כפתורי "דברו איתנו" בעמוד החבילות ובפורטל.

**עדכון מסד נתונים קיים:** הריצו שוב את `supabase/schema.sql` (בטוח להרצה חוזרת). הקובץ יוצר את הטבלאות `service_requests` ו-`service_items`.

## הרחבות עתידיות (לא כלולות ב-MVP הזה)

- **Google OAuth אמיתי:** הכפתור קיים במסך ההתחברות אך מנוטרל. להפעלה: הגדירו OAuth consent screen ב-Google Cloud Console, הוסיפו את ה-Client ID/Secret תחת Supabase → Authentication → Providers → Google, והחליפו את הכפתור המנוטרל בקריאה ל-`supabase.auth.signInWithOAuth({ provider: 'google' })`.
- **התראות אמיתיות (Push / SMS / WhatsApp):** ה-MVP לא כולל שכבת התראות; ניתן להוסיף בעזרת Supabase Edge Functions + ספק כמו Twilio.
- **תשלומים/עמלות אמיתיות:** מסך הלידים באדמין מציג עמלה משוערת בלבד (8% לדוגמה) — אין אינטגרציית סליקה.

## מצב דמו (בלי שרת)

`npm run build:demo` בונה גרסה שרצה כולה בדפדפן עם נתונים לדוגמה ובלי Supabase, כולל פאנל לניווט בין כל המסכים (לקוח, שירות מלא ואדמין). מתאים להצגה ללקוחות, למשקיעים או לשותפים. הקוד של מצב הדמו לא נכלל בבנייה הרגילה.
